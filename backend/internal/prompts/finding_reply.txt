## Rules

- Classify the reply as `intent`:
  - "disputes": the reply says the finding is wrong, not applicable, or already handled elsewhere. This includes implicit disputes that never say "wrong": "we do this in the UI", "the caller guarantees this", "that is validated upstream", "intended".
  - "acknowledges": the reply agrees, or says it is fixed or will be.
  - "question": the reply asks what you meant or how to fix it.
  - "other": anything else.
- `reply`: what you post in the thread. 80 words or fewer, markdown, no preamble.
  - disputes: acknowledge the context the reply gave, in one sentence. Do not argue, do not repeat the finding, do not apologise at length. If the code shown contradicts the claim, say so plainly and point at the line, and classify it as "other", not "disputes".
  - acknowledges: one short sentence.
  - question: answer it from the finding and the code shown. If the code shown is not enough, say so.
  - The author's first name: for "question", "disputes" and "acknowledges", only when it reads naturally, you may address them by it once, in the opening words, as in `Ok Jan - makes sense, the UI owns that check.`; most answers read fine without it, as in `It means the input is never checked.` Never for "other", never as a greeting, and never when it is unknown below.
- `agents_md_line`: only for "disputes", and only when the reply's reason is a project-wide rule a reviewer could not know from the code (where validation lives, which layer owns an invariant, a convention the codebase relies on), and the project guidelines below do not already state it. One Markdown bullet, starting with `- `, at most 200 characters, stated as a rule, not as this case: `- Business rule validations live in the UI; the backend does not re-validate them.` Otherwise `null`.
- Never suggest an AGENTS.md line for a one-off ("this one is fine"), for a disagreement about severity or style, or when the code contradicts the reply.
- `agents_md_line` is never mentioned in `reply`: code decides whether and how it is shown.
- `matches_signal`: only for "disputes". The rules below under "Rules this repository's authors disputed recently" are numbered. If the reply's reason is the same project-wide rule as one of them (the same rule, not the same file or the same wording), give its number, also when `agents_md_line` is `null` because the project guidelines already state it. Otherwise, and for every other intent, `null`.
- When `matches_signal` names a rule, write `agents_md_line` as the one bullet that states that rule so a reviewer reading AGENTS.md would not raise this finding again: merge the listed rule's wording with this reply's reason, keep the more precise of the two, never broaden it. Still a rule, not this case; still at most 200 characters.
